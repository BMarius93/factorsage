# Data correctness map

Where each user-visible number comes from, how it is calculated and stored, how the API and UI
show it, and whether anything independent checks it. This map was written before the audit
harness was built, and it is the harness's plan. The "Audit coverage" columns show the state
**after** the audit. `FINAL_DATA_CORRECTNESS_AUDIT.md` has the results.

Paths are relative to the repository root. The labels used in the tables:

- **Existing tests:** what already checked this before the audit.
- **Independent?** Whether an implementation that does not import the production logic checks
  the value. Answered once for before the audit and once for after it.
- **Gap:** what nothing checked before the audit.

## 0. Shared data foundation

| Stage               | What it is                                                                                                                                                                                                                                                                 |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Provider            | FMP `stable/historical-price-eod/full` (paged at 5,000 rows); `income-statement`, `balance-sheet-statement`, `cash-flow-statement` (`period=quarter\|annual`). Source: `packages/fmp/src/client.ts`, `mapping.ts`.                                                         |
| Price semantics     | OHLCV is **split-adjusted and not dividend-adjusted**. `adjClose` is never used. The variant is `split-adjusted-eod-full:v2` (`packages/stock-data/src/ports.ts`).                                                                                                         |
| Statement semantics | `availableFromDate = filingDate + 1 day`. For a restatement with no newer filing date it is `max(filingDate + 1, observedAt)`. Selection is point in time: the latest revision per identity with `availableFromDate <= D` (`packages/domain/src/financial-statements.ts`). |
| Durable store       | PostgreSQL tables `DailyPrice`, `WeeklyPrice`, `FinancialStatement`, `DailyDerivedState` (every indicator, model and blend is a `Decimal(20,8)` column) and `BenchmarkDailyPrice`.                                                                                         |
| Projection          | Redis yearly chunks `stock-data:v2:*`. They are disposable and rebuilt from PostgreSQL.                                                                                                                                                                                    |
| Evaluation frame    | `packages/stock-data/src/evaluation-frame.ts`. It contains closes, the referenced operand columns and Margin of Safety `(IV − close) / IV × 100`, with the provenance gate applied.                                                                                        |

## 1. Dashboard

The request path: `DashboardPage` (`apps/web/src/features/dashboard/components/DashboardPage.tsx`) calls `GET /dashboard` (`apps/api/src/dashboard/dashboard.controller.ts`), which calls `DashboardService.getDashboard`. That service reads `MonitorSignalState` rows in `ACTIVE | PENDING_TRIGGER` joined to `MonitorSignal`. The state is produced by the Monitor worker (`apps/worker/src/monitor/monitor-cycle.ts`, `level-decision.ts`) through the pure reducer `packages/strategy/src/monitor-lifecycle.ts`. The reducer is fed from `projectMonitorEvaluationFrame` (`packages/stock-data/src/monitor-frame.ts`), which combines closed history with the live quote.

## 2. Stock Details

The request path: `apps/web/src/features/stocks/details/*` calls `GET /stocks/:symbol?from&to` (a one-year window) plus `/prices`, `/technicals/daily`, `/intrinsic-values` and `/intrinsic-value-blends` for older history. These are served by `CanonicalStockDataService` (`packages/stock-data/src/service.ts`), which reads the Redis projection of `DailyPrice` and `DailyDerivedState`.

## 7. Audit gaps this audit closes

The first seven items are closed by this audit:

1. An independent reference backtester for **all** 1,000 matrix runs, compared field by field.
2. Independent indicators and intrinsic values over full history for every matrix security.
3. Evaluation frames against the DB and against independent indicators (**frame provenance**).
4. Stock Details: DB → API → UI for a representative symbol set.
5. Monitor → Signal → Dashboard on real data, with expected-absent signals checked.
6. Backtest Results UI: displayed values against the oracle.
7. Look-ahead: statement filing dates, IV provenance, and prefix invariance of the engine.

These remain out of scope, and the final report explains why:

- raw provider vintages (historical restatements);
- corporate actions beyond splits;
- the provider's own filing-date accuracy for filings that it does date.

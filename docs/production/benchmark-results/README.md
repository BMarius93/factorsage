# Benchmark raw results

Every number in `../benchmark-results.md`, `../capacity-model.md` and
`../PRODUCTION-READINESS-REPORT.md` comes from a file here. How each was produced is
`../benchmarks.md`; the exact command sequences are in `drivers/`.

| File                                                                                  | What                                                                                                                                                                                                         | Produced by                                 |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------- |
| `scale-backtests.jsonl`                                                               | one JSON object per backtest-benchmark invocation (scenarios A–I, cold/warm/miss, failure injection)                                                                                                         | `bench:scale-backtests run`                 |
| `F-ordinary-1y-rebuild.interrupted.jsonl`                                             | the 1,000-ordinary one-year run under the previous behaviour (`REBUILD`): its worker's own log events, including the 1,418.7 s window; a container restart interrupted it before the harness wrote a report  | `drivers/phase4a.sh`                        |
| `lru/*.json`, `lru/lru-500.json.gz`                                                   | the stock-cache tier checks: the LRU-500 model check, concurrent readers at 500 and a capacity lowered to 400, promotion and demotion, protected residency before and after a Redis restart and a Redis loss | `bench:stock-cache-tiers`                   |
| `lru/phase3.log`, `phase4.log`, `phase5.log`, `phase8.log`, `chain.log`               | timestamps, exit codes and Redis memory between the steps of each driver                                                                                                                                     | `drivers/*.sh`                              |
| `H-miss-mixed-shared.memory.log`                                                      | available memory and the backtest workers' resident memory every 5 s while four runs hydrated 400 first-time securities (the 11.9 GB peak)                                                                   | `drivers/phase8.sh`                         |
| `audit-after-*.json`                                                                  | the stock-cache audit after each failure test                                                                                                                                                                | `bench:scale-backtests audit`               |
| `protect-killed.stdout`, `tiers-after-protect-kill.json`, `protect-after-kill.stdout` | the protected-tier rebuild killed after 240 s, the tiers it left, and the rebuild run again                                                                                                                  | `data:index-universe -- protect`, `tiers`   |
| `monitor-alone.json`, `monitor-during-H.json`                                         | the Monitor end-of-day benchmark (300 Monitors, 9,000 members), alone and beside four executing backtests                                                                                                    | `apps/worker/src/monitor/capacity-bench.ts` |
| `interactive-load.jsonl`                                                              | one JSON object per interactive load level (5–100 users, with and without four backtests, one and two API processes)                                                                                         | `load:interactive run`                      |
| `browser-journeys.jsonl`                                                              | Chromium page loads during the same windows                                                                                                                                                                  | `apps/web/load-test/browser-journeys.ts`    |
| `submission-probes.jsonl`                                                             | live admission and entitlement probes against the running API                                                                                                                                                | `src/load-test/submission-probes.ts`        |
| `api-redis-restart-probe.log`                                                         | the API's `/health` once a second through a Redis restart                                                                                                                                                    | `drivers/phase5.sh`                         |
| `load-setup.json`                                                                     | the load accounts' creation summary                                                                                                                                                                          | `load:interactive setup`                    |
| `fmp-live-sample-2026-10-23.txt`                                                      | the one real-FMP sample (3 securities, guarded live command)                                                                                                                                                 | `scripts/cloud/fmp-live.sh`                 |
| `synthetic-hydration-single.json`                                                     | the same three-security hydration against the synthetic provider                                                                                                                                             | `bench:scale-backtests hydrate`             |
| `backup-drill.log`                                                                    | the full dump's duration and size, and one large table dumped and restored                                                                                                                                   | `drivers/backup-drill.sh`                   |
| `compose-smoke.log`                                                                   | the production images built and the production Compose stack deployed on the development machine: health, edge, failover, graceful stops, backup and restore scripts                                         | `drivers/compose-smoke.sh`                  |

Everything except `fmp-live-sample-*`, `backup-drill.log` and `compose-smoke.log` ran against the
**synthetic** provider and synthetic histories (`../benchmarks.md`, "What is real and what is synthetic").
